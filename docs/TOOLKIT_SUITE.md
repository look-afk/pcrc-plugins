# PCRC Toolkit Suite — руководство

## Общие правила
Каждый плагин использует существующий `PluginBase.handle(cmd, param)`. Набор не заменяет встроенные функции клиента, серверной панели или Telegram-бота. Все команды начинаются с отдельного префикса.

## Быстрый старт

### Workflow Builder
`wf_help` — справка; `wf_new daily | Ежедневная проверка`; `wf_add daily | Проверить статус сервера`; `wf_show daily`; `wf_export daily`.

### Event Bus
`event_publish build.finished | Сборка завершена`; `event_recent 10`; `event_stats`; `event_clear`.
Журнал локален для файловой системы, ограничен 200 последними событиями.

### Command Studio
`cs_new morning | Подготовка`; `cs_step morning | status`; `cs_show morning`; `cs_list`.
Пресеты — текстовые заготовки. Команды из них не запускаются автоматически.

### Plugin Developer Kit
`pdk_template my_plugin` — выведет стартовый код; `pdk_checklist` — чек-лист перед публикацией.

### Plugin Sandbox
`sandbox_scan <код>` — разбирает переданный исходник через Python AST, не исполняя его. Сканер ищет отдельные риск-маркеры и может пропускать опасные конструкции или выдавать ложные срабатывания. Для проверки недоверенного кода используйте отдельную виртуальную машину/Windows Sandbox с ограниченными правами; не запускайте его на рабочем компьютере.

### PC Benchmark
`bench_run 2` — тест на 1–3 секунды, выделяет до 8 MiB для проверки памяти и использует временный файл для простого I/O-теста. Это не полноценный аппаратный бенчмарк.

### Smart Scheduler
`sched_add 2026-12-31 18:30 | Проверить релиз`; `sched_list`; `sched_done 1`; `sched_delete 1`.
Дата и время трактуются как локальные. Плагин сохраняет список задач, но не гарантирует уведомления в указанное время.

## Хранение и приватность
JSON-файлы данных сохраняются рядом с файлами плагинов в папке `plugins`. Не помещайте в задачи, сценарии, события или пресеты пароли, токены, персональные данные или другие секреты. При удалении плагина файлы его данных автоматически не удаляются — удалите их отдельно, если они больше не нужны.
